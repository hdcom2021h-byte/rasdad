# رصداد — واجهة Static

الصفحة الرئيسية هي `index.html`. الموقع يعمل دون Python أو قاعدة بيانات، ويمكن فتح الصفحة مباشرة أو نشرها على GitHub Pages.

## ملفات الواجهة

- `index.html`: الصفحة الرئيسية.
- `packages.html`: الباقات.
- `services.html`: الخدمات.
- `header.html` و`footer.html`: مصدر المكونات المشتركة.
- `media/`: الصور والتنسيقات والبرامج، ومنها `components.js` الذي يحمّل الهيدر والفوتر دون fetch.

نماذج الطلب والتواصل والتقييم تجهّز رسالة إلى واتساب 0563962821. يضغط العميل إرسال داخل واتساب لإتمام التواصل. لا تُحفظ البيانات في الموقع ولا يُدّعى استلامها تلقائيًا. التقييم يتكون من الاسم والنجوم فقط. لا يوجد عداد زوار مشترك أو نشر تلقائي للتقييمات؛ يتطلب ذلك خدمة خارجية غير مربوطة بهذه النسخة.

## التجهيز والنشر

ملف `media/components.js` جاهز ومضمّن في المشروع. عند تعديل الهيدر أو الفوتر، نفّذ `node scripts/prepare-static.mjs` لتحديثه وتجهيز ملفات النشر داخل `_site/`. Node أداة تجهيز فقط، ولا يحتاج الموقع إليه عند الاستخدام.

تم إعداد `.github/workflows/pages.yml` ليجهّز ملفات الواجهة فقط وينشر مجلد `_site/`. في إعدادات المستودع اختر **Settings → Pages → Source → GitHub Actions**، ثم ارفع التعديلات إلى `main` أو شغّل workflow يدويًا. المصدر: [دليل GitHub Pages الرسمي](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

عند رفع الموقع يدويًا إلى استضافة Static، ارفع محتويات `_site/` فقط. الروابط نسبية لتعمل تحت مسار المستودع `/rasdad/`. لا يحتاج النشر إلى تثبيت Python أو تشغيل `server.py`.

## ملفات محفوظة وغير مطلوبة للنشر

- `server.py` و`start.ps1` و`test_server.py`: خاصة بالنسخة السابقة التي تستخدم Python.
- `admin.html`: لوحة الإدارة القديمة وتحتاج API؛ لا تدخل في حزمة النشر.
- `data/` وقواعد البيانات و`__pycache__/`: بيانات محلية وكاش، ولا تدخل في النشر.
- `README.md` و`.gitignore` و`.git/`: توثيق وإدارة المشروع.
- `scripts/` و`.github/`: تجهيز ونشر فقط وليسا من ملفات الموقع المعروضة.

لم تُحذف ملفات النسخة السابقة. اختبارات `test_server.py` تخص الخادم القديم ولا تُشغّل عند تجهيز الواجهة.
